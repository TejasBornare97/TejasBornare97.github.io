Case study / Voice agent

Voice Receptionist

A voice agent that answers calls for a physiotherapy clinic. It listens, checks a real Google Calendar, books the appointment and confirms it out loud. Callers can cut in mid-sentence, the way they would with a person.

RoleSolo, end to end
Stackfaster-whisper, Piper, Claude tool use, Google Calendar API
Runs onLocal speech, hosted LLM
View code on GitHub ↗

A real test call

Receptionist Hello, you're through to Riverside Physio. How can I help you today?

Caller Can I book something on Wednesday?

check_availability(date="2026-11-11") → 10 free slots

Receptionist Yes, we have Wednesday the eleventh free from nine in the morning until a quar…

caller interrupts

Caller Sorry, actually make it Thursday.

check_availability(date="2026-11-12") → 10 free slots

Receptionist No problem, Thursday the twelfth has the same times free. Is there a time of day that suits you best?

book_appointment(date="2026-11-12", time="12:00") → confirmed, ref A42ACE

Receptionist Your appointment is booked for Thursday the 12th of November at noon. Your booking reference is A42ACE.

The booking then appears in the clinic's Google Calendar with the caller's name, number and reference.

How a turn works

  1. Listen. Audio in 30 ms blocks. The caller has finished after 800 ms of quiet, measured against a noise level calibrated at the start of the call.
  2. Transcribe. Whisper (int8, on CPU) with a short hint about the call, which helps with times and phone numbers.
  3. Think. The LLM gets the conversation and three tools: check_availability, book_appointment and end_call.
  4. Act. A tool runner validates every request and talks to Google Calendar.
  5. Speak. Piper synthesises the reply while the microphone keeps listening for interruptions.

Design decisions

Business rules live in code, not the prompt

The model never writes to the calendar directly. Tools reject weekends, past dates, bad phone numbers and taken slots.

The slot is re-checked right before booking, so two callers can't take the same time.

Errors go back to the model

If a slot is gone or the API fails, the tool returns an error with a hint instead of crashing.

The agent recovers in conversation, for example by offering another time.

Interruptions have to mean it

Coughs and echo were cutting the receptionist off.

While she's talking, the caller must be 3.5× louder than normal for about 360 ms of a 450 ms window. If an interruption has no words, she picks up where she left off.

The conversation broke every minute

The system prompt included the current time and was rebuilt each turn. The model's reasoning is tied to the prompt it was produced with, so the call failed whenever the minute changed.

The prompt is now built once, when the call starts.

Phone numbers read as billions

TTS read a mobile number as "seven billion, eight hundred and sixty-seven million…".

Long digit strings are rewritten as spoken digits in UK groupings before speech.

Bluetooth cut off the first second

Opening the microphone per turn made headsets switch audio mode.

The microphone stays open for the whole call.

Built to test fast

The calendar sits behind one interface with an in-memory version and a Google version, so development needs no Google account. A text mode runs the same agent with typed input, which makes testing conversation logic far quicker than speaking every turn.

What I'd do next

  • A model-based voice activity detector (such as Silero) for noisy rooms
  • Streaming speech sentence by sentence to cut reply latency
  • Echo cancellation so it works on laptop speakers, not just a headset
  • A real phone line through Twilio
